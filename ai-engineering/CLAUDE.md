# AI 应用工程 · AIPE

大白话讲透「怎么把一个 AI 能力从演示做到能上岗」（科普通识，非工程方案与投资测算依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→AIPE 命名空间替换），内容完全重写。「今日得到」合集第 48 站。

## 站点定位

- **给谁看**：要把 AI 能力真正接进业务系统的售前、项目经理、交付实施与研发人员；以及需要把「这个东西到底能不能上线、值不值得投」讲清楚、写进方案与汇报里的商务与技术角色。
- **讲什么**：从 Demo 到生产的鸿沟（演示鸿沟、快乐路径、分布漂移、长尾输入、失败模式、幻觉与非确定性、护栏），场景筛选与需求定义（场景筛选、任务分解、工作单元、验收标准、容错度、人在回路、适配度评估、变革管理），Harness 编排层（编排、提示词与模板、工具与函数调用、智能体循环、工作流图、输出校验、重试与降级），上下文与知识供给（上下文窗口与预算、RAG、切块、向量化与检索、重排、落地依据、记忆），评测体系（评测集与黄金集、离线与在线评测、模型裁判、评分标准、准确率与召回率、回归测试、评测驱动开发），可观测性与线上监控（链路追踪、Token 计量、漂移监控、质量抽检、告警、事故分级），灰度、A/B 与发布（影子模式、灰度、A/B、特性开关、统计显著性、回滚与发布门禁），成本与 Token 经济（计价差异、缓存、模型分层、批处理、单任务成本、单位经济、预算上限），价值度量与结果定价（价值指标、北极星、三种定价、基线与反事实、价值实现周期），数据飞轮与冷启动（飞轮、冷启动、反馈闭环、人工反馈、合成数据、标注），人机协同与组织适配（增强而非替代、分工、岗位重塑、审核负荷、自动化偏见、技能迁移、采纳曲线），安全与合规（KYA、提示词注入、数据泄露、越狱、权限最小化、审计留痕、合规审查），ROI 论证与汇报（ROI、TCO、回收期、净现值、收益量化、试点到规模化），实战案例与失败复盘。
- **不讲什么**：模型原理与训练算法（另有专站）、算力基建与算电协同（另有专站）、云原生方法论（另有专站）、安全通识（另有专站）、具体厂商产品与报价、真实的统计与财务建模细节。重「工程逻辑与判断口径」，轻「产品与规格」。
- **调性**：大白话、五分钟一课、有判断。先给一句人话，再展机制，最后落到「所以工程上该怎么做」。

## 与兄弟站的关系

- **artificial-intelligence（人工智能）** 讲 AI 通识；**ML（机器学习）** 讲算法与训练；**AGT（AI 智能体）** 讲智能体本身；**AIC（AI 算力基础设施与算电协同）** 讲算力与供电散热；**CCN（云计算与云原生）** 讲云上方法论；**information-security（信息安全）** 讲安全通识；**DAT（数据分析通识）** 讲数据；**AIP（人工智能+电力）** 讲电力行业应用场景。
- **本站（AIPE）** 补的是这些站都不覆盖的一段：**把模型能力做成一个能上线、能评测、能运营、能算清账的业务系统**——也就是「模型之外的工程」。因此本站不重复讲模型原理、不重复讲训练算法、不重复讲算力基建、不重复讲云原生、不重复讲安全通识。

## ⚠️ 技术与合规（本站最硬的约束）

1. **内容基线：2026 年 10 月**。`index.html` 顶栏声明条、首页「技术与合规声明」块、模块页提示、`CLAUDE.md` 四处均写明该日期；基线前移时同步更新。
2. **不写厂商名、不写报价、不写真实型号与版本号**。所有平台与模型描述停留在「能力与形态」层面。
3. **不编造标准编号与政策文号**。涉及安全、合规、个人信息与监管之处，只写思路、边界与口径，一律注明「以现行有效标准与企业制度为准」。
4. **不给出结论性的选型或投资建议**。工具只给判断思路与量级，最终须以官方文档、自身业务数据与财务口径为准。
5. **工具结果的免责**：七件互动工具均为极度简化教学测算，必须注明「不作为工程方案、采购决策、投资测算或合规依据」。

## 7 个互动工具（views-tools.js）

1. **Token 成本与调用量测算器**（`AIPE.calcTokenCost`）：日调用量与平均输入/输出 Token + 两类单价 + 缓存命中率与读取价折扣 + 月天数 → 日均 Token、输入输出分项成本、日/月/年成本、单次调用成本、输入占成本比、缓存节省
2. **RAG 检索质量与上下文预算测算器**（`AIPE.calcRagBudget`）：窗口 + 系统与输出预留 + 单条片段 Token + 召回 K + 重排保留数 + 命中率与兜底正确率 → 检索预算、K 条占用、预算内最多能放几条、重排前后上下文占用率、重排省下的 Token、综合可信作答率（命中率 + 未命中时的兜底正确率）
3. **评测集与指标设计器**（`AIPE.calcEvalDesign`）：样本数 + 正确率 + 允许误差 + z 值 + 场景类别数 + 每类最少样本 → 最小样本量 n = z²p(1−p)/e²、缺口、当前误差半宽、按类别均分与场景覆盖要求、建议目标规模
4. **灰度分流与效果显著性估算器**（`AIPE.calcRolloutTest`）：日均流量 + 灰度比例 + 实验天数 + 基准转化率 + 期望提升 + 显著性与功效 z 值 → 每组所需样本、已累积样本、是否够检、还需天数、最小可检出差异
5. **AI 项目 ROI 测算器**（`AIPE.calcRoi`）：建设投入 + 年平台调用与运维 + 年节省工时与人力单价 + 年增收降损 + 年限 + 折现率 → 年收益/年成本/年净收益、累计净收益、ROI、回收期、净现值 NPV
6. **人工替代与效率增益测算器**（`AIPE.calcEfficiency`）：年任务量 + 人工与 AI 单件耗时 + 审核比例与审核耗时 + 一次通过率 + 人工小时成本 + 年人均工时 → AI 处理/审核/返工三类工时、总工时、节省工时与比例、年节省成本、等效释放人力
7. **失败模式自诊器**（`AIPE.calcFailureDiag`）：输入相似度、评测集、护栏、人工兜底、线上监控、上线方式六项 0/1/2 打分 → 总分与档位、逐项判定、最弱一环及其风险说明与下一步动作、其余高风险项清单

工具用 `oninput="AIPE.calcXxx()"` 即时计算（不是按钮触发），`AIPE.views.calc` 渲染后立即调用七个函数出首屏结果。

## 内容源写法陷阱

- ⚠️ **本站引擎（IOT 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`（课时元组**顶格从 `[` 开始、不缩进**）
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>前文' + g('rag','RAG') + '后文</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号。正文标点沿用全站既有风格：**逗号/冒号/问号/分号用半角**（`,` `:` `?` `;`），**句号用全角 `。`**，引号用「」。
  - 模块 id `eval` 是合法属性名，裸赋值写 `L.eval = [` 即可，内链写 `#/l/eval/01-why-eval`。
  - **必须在写课时前先把 `TERMS` 定死并产出「可用术语 id 白名单」**，agent 只能用白名单内 id，否则构建会因 `data-term` 未定义而报错。
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。克隆基座后要**先删掉旧的 `<script src="content/...">` 标签**（保留 `modules.js` 与 `terms.js`），否则新旧脚本会同时加载。
- 克隆基座的命名空间替换要跑三遍（本次 IOT→AIPE 实测）：① `perl -pi -e 's/\bIOT\b/AIPE/g'`（BSD `sed` 无 `\b`）；② 兜底 `perl -pi -e 's/IOT\./AIPE./g'`——`\b` 在 `'...\nIOT.terms = '` 这类**字符串字面量**里会失效；③ **驼峰标识符**（`iotSVG` / `iotup0` / `iotdn0`）正则抓不到，需单独替换（本站已随 views 重写清除）。同理 `progress/iot-sensing.json` 要替换为 `progress/ai-engineering.json`，导出文件名 `iot-progress-*.json` → `aipe-progress-*.json`。
- **`cp -R` 克隆时若目标目录已存在会套一层**（本次踩到：出现 `ai-engineering/iot-sensing/`），克隆后必须 `ls` 确认没有多余嵌套。
- **macOS 的 BSD grep 不支持 `\|` 与 `\s`，且对中文行会假阴性**——验证残留时中文关键词一律用 Grep 工具（ripgrep）查，不要用 Bash `grep`。
- 统计课时数不要用 grep 数行（课时元组顶格 + 中文行假阴性）；用 `node` 求值精确统计。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语标注覆盖 115 个术语中的绝大多数，分布在各模块。
