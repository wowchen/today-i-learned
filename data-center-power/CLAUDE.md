# data-center-power — 数据中心与算电协同（Today I Learned 第 54 站）

大白话讲透「数据中心里的电怎么进来、怎么变成算力、制冷吃掉多少、算力又怎么反过来调节电」（科普通识，非工程设计、设备选型、采购、投资或结算依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→DTC 命名空间替换），内容完全重写。「今日得到」合集第 54 站。

## 给谁看 / 讲什么 / 不讲什么 / 调性
- **给谁看**：数据中心的运维与能效管理岗、机房与基础设施工程师、要评估数据中心用能与绿电的能源从业者、做算电协同与算力调度的产品与运营人员，以及想读懂「PUE」「液冷」「东数西算」「算电协同」新闻的普通人。
- **讲什么**：数据中心的**电与算的链路**——数据中心是什么 → 电怎么供配电进来 → 制冷怎么把热带走 → 负荷有什么特性 → 用能怎么管 → 怎么变绿 → 算电协同的原理 → 算力怎么调度和参与需求响应 → 怎么进虚拟电厂 → 储能怎么配 → 高压直流怎么提效 → 智算中心有什么不同 → 政策与市场怎么看 → 真实案例怎么做。
- **不讲什么**：不重复 AI 算力基础设施的宏观技术与算力网络（`ai-compute`）、不重复云原生与容器编排（`cloud-native`）、不重复数据管道与数仓建设（`data-engineering`）、不重复电网的物理原理（`power-grid-fundamentals`）、不重复虚拟电厂的聚合商业模式细节（`virtual-power-plant` 本站兄弟 VPP）。本站讲的是**机房里的电与算怎么互相咬合**。
- **调性**：大白话、口语化、给具体数字例子（PUE 降到 1.2 能省多少度、一台变压器扛多少 kVA、可中断负载能申报多少 kW），每课都给「能带走的一个判断」。

## 技术与合规约束（必须有）
1. **常驻声明**：`index.html` 的 `.notice-bar`、首页 `.disclaimer`、课时页模块提示三处都要有，基线 **2026-10**。
2. **不构成依据**：`.notice-bar` 写明「本站不构成工程设计、设备选型、投资测算、采购或合规依据」；首页 `.disclaimer` 写明「本站为通识科普，不构成工程设计、设备选型、采购、投资或结算依据」；课时页模块提示写明「本站不构成工程设计、设备选型、采购、投资或合规依据」。
3. **口径随文件变**：涉及能耗与 PUE 要求、绿电采购、需求响应、算力调度与数据中心相关政策之处，一律标注「以现行有效的国家标准、行业规范、主管部门文件与市场规则为准」。
4. **时效性强**：PUE/WUE 限值、绿电比例要求、需求响应与算力调度规则变化快，正文一律写「示例概数」并提醒读者核对最新标准。
5. **不引战、不预测**：不对技术路线与政策松紧作预测或倾向性评价；只讲机制与算法怎么运作。

## 7 件互动工具（`views-tools.js`）
| 函数 | 结果容器 | 算法要点 |
|---|---|---|
| `calcDcEnergy` | `de-result` | 供配电损耗 = IT 功率 × 损耗率；总功率 = IT + 制冷 + 损耗 + 其他；PUE = 总功率 ÷ IT；年耗电量 = 总功率 × 8760；IT 与全站功率密度 = 功率 ÷ 面积；再按制冷降幅算改善后 PUE 与年节电量 |
| `calcPowerCapacity` | `pc-result` | 计算负荷(kVA) = IT 功率 × 同时系数 ÷ 功率因数；所需总容量 = 计算负荷 ÷ 负载率上限；所需台数向上取整；按 N / N+1 / 2N 配台数与总容量；实际负载率并判定「失去一台（或一半）后是否仍能带全部负荷」 |
| `calcCoolingLoad` | `cl-result` | 显热制冷量 ≈ IT 功率；总冷负荷 = 显热 × 附加系数；送风量 = Q ÷ (1.2 × 1.005 × 送风温差)；冷冻水流量 = Q × 3600 ÷ (4.18 × 1000 × 供回水温差)；COP 取风冷 3 / 水冷 5 / 液冷 7；制冷能耗 = 总冷负荷 ÷ COP，得制冷占比与对应 PUE 贡献 |
| `calcGreenPower` | `gp-result` | 绿电电量 = 年用电量 × 采购比例；绿证数量 = 绿电电量(MWh) ÷ 每张对应电量；采购成本 = 绿证数 × 单价；减排量 = 绿电电量 ×（电网因子 − 绿电因子）；再算剩余排放与碳排强度(kgCO₂/kWh) |
| `calcDrRevenue` | `dr-result` | 单次响应电量 = 可削减负荷 × 单次时长；年响应电量 = 单次 × 次数；容量收益 = 可削减负荷 × 容量补贴；电量收益 = 年响应电量 × 度电补贴；考核后收益 = 合计 × 考核系数；单 kW 年收益 |
| `calcSynergyFlex` | `sf-result` | 可调节负载 = IT 功率 × 可迁移/可中断占比；可上/下调容量 = 可调节负载 × 调节深度；有效调节时长 = min(可调节时段, 时延容忍度)；可调电量 = 可下调容量 × 有效时长；等效储能容量 = (上调 + 下调) × 有效时长；日可调节次数 = 24 ÷ 有效时长 |
| `calcDcCost` | `dc-cost-result` | 峰/平/谷电量电费（平段电价由平均电价反算）；基本电费 = 最大需量 × 需量单价 × 12；年电费合计与综合到户电价；峰谷优化：把峰段电量按比例转移到谷段，算节省与优化后电价；最后给度电成本构成占比 |

## 内容源写法陷阱（`tools/_src/*.js`）
- 本站引擎（IOT 系）的 `_src/*.js` 是「**裸赋值 + helpers**」写法：`L.<moduleid> = [ ... ];`（如 `L.synergy`），由 `build.js` 用 `eval()` 加载，**不要写 `module.exports`**。
- helpers 只有 `g/ex/pit/fml/qc`，**没有 `qf`**；只能在引号外用 `+` 拼接。
- ⚠️ `L.eval = [` 这类模块 id 若恰好叫 `eval`，会与 `eval()` 冲突——本站无此问题，但命名模块时留意保留字。
- 课时元组**顶格从 `[` 开始**（不要缩进），9 元素：`[slug, 标题, 分钟, [关键词], concept, core, pitfalls, quiz数组, links]`。
- ⚠️ **`core` 必须是数组**（每项一个「小标题 + 正文」块）；写成字符串会导致 `build.js` 抛 `(les[7] || []).forEach is not a function`。
- concept 必须以「一句话:」开头；逗号/冒号/问号/分号用**半角**，句号用**全角 `。`**；引号「」，破折号 `——`；**禁止 emoji**。
- `tools/_src` 文件用 `NN-<moduleid>.js` 编号；插入模块后必须 `mv` 重排编号。
- ⚠️ **`cp -R` 克隆时若目标目录已存在会套一层**；克隆后必须 `ls` 确认没有多余嵌套。
- ⚠️ BSD/macOS 的 `sed` 无 `\b`（用 `perl -pi -e`）；Bash `grep` 查中文行易假阴性（用 Grep 工具/ripgrep）。
- ⚠️ **zsh 不对未加引号的 `$VAR` 做词分割**：`perl -pi -e '...' $FILES` 会把整串当一个文件名（报 `File name too long`），须改用 `find ... -print0 | xargs -0 perl -pi -e '...'`。
