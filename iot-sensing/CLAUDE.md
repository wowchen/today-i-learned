# 电力物联网与感知层 · IOT

大白话讲透电力物联网与感知层（科普通识，非工程设计与采购依据）。克隆 `power-marketing`(EMK) 共享引擎（EMK→IOT 命名空间替换），内容完全重写。「今日得到」合集第 43 站。

## 站点定位

- **给谁看**：做电力信息通信、配网智能化、跨域集成的售前、项目经理、交付实施与运维人员；以及需要把「感知层到平台这一段」讲清楚、写进方案里的商务与技术角色。
- **讲什么**：电力物联网全景、通信模组与物联网卡、物联网卡全链路监测、公网与电力专网、载波与本地通信、传感器与智能终端、边缘计算与网关、设备接入与物联网平台、感知数据治理与数据质量、感知层安全、典型场景实战、感知层运维与缺陷处置、项目建设与运营。
- **不讲什么**：具体厂商型号与报价、真实的频段许可与标准编号、具体工程的设计计算、招投标条款。重「架构与判断」，轻「型号与参数」。
- **调性**：大白话、五分钟一课、有判断。先给一句人话，再展机制，最后落到「所以选型/方案该怎么想」。

## 与兄弟站的关系

- **TCM（通信通识）** 讲传输光网络本身（SDH/OTN/PON）；**CCN（云计算与云原生）** 讲云上方法论；**PDN（配电网与配电自动化）** 讲配电网架与自动化；**ISL（信息安全）** 讲安全通识；**PGF（电网通识）** 讲电力系统原理。

## 7 个互动工具（views-tools.js）

1. **物联网卡流量池测算器**（`IOT.calcTraffic`）：卡数 + 单卡月流量与套餐价 + 池化单价 + 池容量与实际用量 → 独立套餐月成本、流量池月成本、月/年节省、节省比例、池利用率与超池警示
2. **链路可用率测算器**（`IOT.calcAvailability`）：卡/模组、无线网络、专线、平台四段可用率 → 端到端可用率（四段**串联相乘**，不是取平均）、年中断时长、瓶颈段识别、最弱段提升 1 个百分点后的改善量
3. **通信方式选型器**（`IOT.calcCommChoice`）：业务类型 + 数据量 + 上报频率 + 时延要求 + 是否有频段 → 推荐制式（电力无线专网 / 5G 切片 / 公网 4G / NB-IoT / LoRa / HPLC）+ 推荐理由 + 不推荐项及原因
4. **边缘数据量与带宽测算器**（`IOT.calcEdge`）：点位数 + 站点数 + 采集频率 + 包大小 + 聚合倍率 + 变化上报率 → 原始与处理后日数据量、节省比例、所需上行带宽、月流量
5. **终端功耗与电池寿命测算器**（`IOT.calcPowerBudget`）：电池容量 + 可用比例 + 休眠电流 + 上报次数与单次时长 + 上报期间平均电流 + 目标寿命 → 每日工作/休眠耗电与占比、日均耗电、可用电量、预计寿命（天/年）、目标下允许日耗电与允许上报次数、省电着力点判断
6. **点位与采集频度规划器**（`IOT.calcPointPlanning`）：上行可用带宽 + 站点数 + 单站点点位 + 报文大小 + 采集间隔 + 协议开销 + 突发系数 + 健康占用上限 → 单点/单站点平均与峰值速率、带宽占用率、健康预算、可承载点位上限与余量、该带宽下最快采集间隔、所需带宽、全网月数据量
7. **感知层造价估算器**（`IOT.calcCost`）：点位数 + 终端/通信/施工单价 + 平台分摊 + 年运维系数 → 四项分项合计、总投资、各项占比、首年含运维投入、单点综合造价

工具用 `oninput="IOT.calcXxx()"` 即时计算（不是按钮触发），`IOT.views.calc` 渲染后立即调用七个函数出首屏结果。

## 内容源写法陷阱

- ⚠️ **本站引擎（EMK 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**，与 NPS 系的 `module.exports = [...]` 完全不同：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>前文' + g('hplc','HPLC') + '后文</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号。正文标点沿用全站既有风格：**逗号/冒号/问号/分号用半角**（`,` `:` `?` `;`），**句号用全角 `。`**，引号用「」。全站 `_src` 文件里全角逗号与全角冒号的出现次数均为 0。
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。克隆基座后要**先删掉旧的 `<script src="content/...">` 标签**（保留 `modules.js` 与 `terms.js`），否则新旧脚本会同时加载。
- 克隆基座的命名空间替换要跑两遍：`sed` 之后还有两个坑——① **`\b` 词边界在 macOS 的 BSD sed 里不生效**，必须用 `perl -pi -e 's/\bEMK\b/IOT/g'`；② `emkSVG` / `emkup0` 这类**驼峰标识符**（`emk` 后面紧跟字母，无词边界）正则抓不到，需单独处理（本站已随 views 重写清除）。同理 `progress/power-marketing.json` 要单独替换为 `progress/iot-sensing.json`。
- **macOS 的 BSD grep 不支持 `\|` 与 `\s`**，验证残留时要用 `grep -E 'A|B'`，否则会得到"没有残留"的假阴性。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语标注覆盖全部 110 个术语，分布在各模块。
