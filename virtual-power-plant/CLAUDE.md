# virtual-power-plant — 虚拟电厂（Today I Learned 第 55 站）

大白话讲透「散落的空调、储能、电动车、光伏怎么聚成一座能参与市场的电厂、怎么调、怎么分钱」（科普通识，非项目决策、投资测算、报价、结算或法律依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→VPP 命名空间替换），内容完全重写。「今日得到」合集第 55 站。

## 给谁看 / 讲什么 / 不讲什么 / 调性
- **给谁看**：虚拟电厂与综合能源服务商的运营与产品岗、聚合平台与负荷集成商的技术与商务人员、工商业园区与物业的能源管理岗、充电运营商与储能业主，以及想读懂「需求响应」「V2G」「聚合商」「车网互动」新闻的普通人。
- **讲什么**：虚拟电厂的**聚合与分钱链**——虚拟电厂是什么 → 为什么需要 → 有哪些可调节资源 → 平台怎么搭 → 可调能力怎么算 → 需求响应怎么参与 → 辅助服务怎么挣 → 现货怎么报 → 商业模式怎么设计 → 标准与准入怎么守 → 电动汽车怎么聚合 → 工商业与园区怎么做 → 居民社区怎么做 → 国内外怎么实践 → 项目怎么落地。
- **不讲什么**：不重复储能设备与配置（`new-power-storage`）、不重复现货报价与结算的操作细节（`power-spot-market` 本站兄弟 SPOT）、不重复数据中心内部的供电制冷与算电协同（`data-center-power` 本站兄弟 DTC）、不重复配电网规划与运行（`power-distribution`）、不重复电力市场的制度全貌（`power-market`）。本站讲的是**把一堆零散资源聚成一个可调度、可交易、可分钱的整体**。
- **调性**：大白话、口语化、给具体的账（能调多少 kW、一年响应几次、分成怎么切、一户多拿几百还是几千），每课都给「能带走的一个判断」。

## 与兄弟站的边界
| 站 | 讲什么 | 本站不重复的地方 |
|---|---|---|
| `new-power-storage` 新型电力系统与储能 | 储能设备、电池与系统集成 | 只把储能当作一类可调资源，不拆设备与化学体系 |
| `power-spot-market` 电力现货与交易实务 | 现货报价、结算、偏差与风控操作（本站兄弟 SPOT） | 只讲虚拟电厂以聚合主体身份怎么参与，不做报价与结算实操 |
| `data-center-power` 数据中心与算电协同 | 数据中心供配电、制冷与算力调节（本站兄弟 DTC） | 只把可中断算力当作一类资源，不展开机房内部 |
| `power-distribution` 配电网 | 配网规划、运行与接入 | 不讲配网本体，只讲资源怎么被聚合与调用 |
| `power-market` 电力市场 | 交易品种、出清与结算制度 | 只讲聚合商如何在制度内参与，不铺开市场制度 |
| `power-marketing` 电力营销 | 客户服务与营销业务 | 不涉营销话术，只讲签约与收益分配机制 |

## 技术与合规约束（必须有）
1. **常驻声明**：`index.html` 的 `.notice-bar`、首页 `.disclaimer`、课时页模块提示三处都要有，基线 **2026-10**。
2. **不构成依据**：`.notice-bar` 写明「本站不构成项目决策、投资测算、报价、结算或法律依据」；首页 `.disclaimer` 写明「本站为通识科普，不构成工程设计、投标、投资测算、报价或结算依据」；课时页模块提示写明「本站不构成工程设计、采购、招标、投资测算或合规依据」。
3. **口径随文件变**：涉及聚合商准入、资源接入规范、需求响应补偿、辅助服务与市场参与规则之处，一律标注「以现行有效的国家标准、主管部门文件、市场规则与结算办法为准」。
4. **时效性强**：需求响应补偿标准、基线核定方法、聚合商准入条件与辅助服务价格变化快，正文一律写「示例概数」并提醒读者核对最新文件。
5. **不引战、不预测**：不对商业模式回报、试点推进节奏作预测或倾向性评价；只讲机制与算法怎么运作。

## 7 件互动工具（`views-tools.js`）
| 函数 | 结果容器 | 算法要点 |
|---|---|---|
| `calcAggCapacity` | `ac-result` | 名义可调容量 = 各类资源数量 × 单体可调容量之和；有效可调容量 = 名义容量 × 同时率 × 可用率；按要求的响应速度等级（秒级/分钟级/小时级）筛出够快的资源算占比；折合单户平均容量 = 有效容量 ÷ 资源单元数 |
| `calcDrIncome` | `dr-result` | 单次响应电量 = 有效响应容量 × 单次时长；年响应电量 = 单次 × 次数；容量收益 = 容量 × 容量补贴；电量收益 = 年响应电量 × 度电补贴；考核后总收益 = 毛收益 × 考核系数；再按分成比例切出聚合商分成与资源方实得 |
| `calcBaseline` | `bl-result` | 响应量 = 响应时段基线负荷 − 实际负荷；响应电量 = 响应量 × 时段长度；核定响应量 = 响应量 × 核减系数（平均法 1.00 / 前 N 日最大 0.95 / 前 3 日相似日 0.90）；与门槛比判定本次响应是否有效，并算核减量与核减率 |
| `calcAggregatorSplit` | `as-result` | 聚合商毛收入 = 项目总收益 × 分成比例；净收益 = 毛收入 − 平台成本 − 保底补贴；资源方分成总额 = 总收益 − 毛收入；单户实得 = 单户分成 + 保底补贴摊到每户；平台单位资源成本 = 成本 ÷（资源数 × 单户容量）；盈亏平衡资源数 = 平台成本 ÷ 单户毛贡献 |
| `calcAncillaryVpp` | `av-result` | 年里程/电量 = 申报容量 × 调用次数 × 单次时长；容量基准收益 = 申报容量 × 容量单价（支持元/kW·月折年）；容量收益 = 基准 × 性能折算；里程收益 = 基准 × 考核系数 × 性能折算；折减额与单位容量收益 = 合计 ÷ 申报容量 |
| `calcV2gIncome` | `v2g-result` | 实际参与车辆 = 车辆数 × 可参与率；总可调容量 = 车辆 × 单车可调容量；年放电量 = 总容量 × 每天时长 × 天数；毛收益 = 年放电量 × 放电电价；净收益 = 毛收益 − 充电成本 − 电池折损成本；单车年收益 = 净收益 ÷ 实际参与车辆数 |
| `calcVppInvest` | `vi-result` | 年净收益 = 年收益 − 年运营成本；静态回收期 = 投资 ÷ 年净收益；NPV = Σ 年净收益÷(1+r)^t + 残值÷(1+r)^n − 投资；IRR 用二分法（区间 [−0.9, 2]，迭代 200 次）解 NPV = 0；投资回报倍数 =（年净收益 × 年限 + 残值）÷ 投资 |

## 内容源写法陷阱（`tools/_src/*.js`）
- 本站引擎（IOT 系）的 `_src/*.js` 是「**裸赋值 + helpers**」写法：`L.<moduleid> = [ ... ];`（如 `L.aggregation`），由 `build.js` 用 `eval()` 加载，**不要写 `module.exports`**。
- helpers 只有 `g/ex/pit/fml/qc`，**没有 `qf`**；只能在引号外用 `+` 拼接。
- ⚠️ `L.eval = [` 这类模块 id 若恰好叫 `eval`，会与 `eval()` 冲突——本站无此问题，但命名模块时留意保留字。
- 课时元组**顶格从 `[` 开始**（不要缩进），9 元素：`[slug, 标题, 分钟, [关键词], concept, core, pitfalls, quiz数组, links]`。
- ⚠️ **`core` 必须是数组**（每项一个「小标题 + 正文」块）；写成字符串会导致 `build.js` 抛 `(les[7] || []).forEach is not a function`。
- concept 必须以「一句话:」开头；逗号/冒号/问号/分号用**半角**，句号用**全角 `。`**；引号「」，破折号 `——`；**禁止 emoji**。
- `tools/_src` 文件用 `NN-<moduleid>.js` 编号；插入模块后必须 `mv` 重排编号。
- ⚠️ **`cp -R` 克隆时若目标目录已存在会套一层**；克隆后必须 `ls` 确认没有多余嵌套。
- ⚠️ BSD/macOS 的 `sed` 无 `\b`（用 `perl -pi -e`）；Bash `grep` 查中文行易假阴性（用 Grep 工具/ripgrep）。
- ⚠️ **zsh 不对未加引号的 `$VAR` 做词分割**：`perl -pi -e '...' $FILES` 会把整串当一个文件名（报 `File name too long`），须改用 `find ... -print0 | xargs -0 perl -pi -e '...'`。
