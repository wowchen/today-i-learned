# 电力营销与客户服务 · EMK

大白话讲透电力营销与客户服务（科普通识，非业务办理指南）。克隆 `power-market`(EMT) 共享引擎（EMT→EMK 命名空间替换），内容完全重写。「今日得到」合集第 42 站。

## 站点定位

- **给谁看**：需要跟客户、电费、办电、计量、服务打交道的非营销岗——售前、项目经理、交付、设备与运维、能源服务与商务人员；以及刚接触营销业务、想把这条线理顺的人。
- **讲什么**：营销业务全景、电价与电费构成、抄表核算收费、电能计量、业扩报装、客户服务与供电质量、需求侧管理与能效、市场环境下的营销变革、营销数字化、用电检查与稽查、政策与合规、一线实战。
- **不讲什么**：具体省份的电价表数字、业务系统的按键操作、政策文号逐条复述、任何规避监管的做法。重「业务逻辑与判断」，轻「流程条数与系统操作」。
- **调性**：大白话、五分钟一课、有判断。每个概念先给一句人话，再展开。案例数字均为教学演示。

## 与兄弟站的关系

- **EMT（电力市场与能源交易）** 回答「电怎么交易、价格怎么形成」；**PDN（配电网与配电自动化）** 回答「配电网怎么搭、怎么自动化」；**FIN（企业财税与内控审计）** 回答「企业怎么算账、怎么防舞弊」；**本站（EMK）** 回答「电网企业面向客户的这条线怎么运转」。
- 本站不重复 EMT 的市场机制与交易规则（只讲到「客户如何选择购电方式」为止），不重复 PDN 的网架与自动化技术，不重复 PGF 的电力系统原理。

## ⚠️ 政策与合规（本站最硬的约束）

本站涉及电价政策、收费标准、办电时限、服务规范与监管要求，**政策变化频繁**。因此：

1. **内容基线：2026 年 9 月**。首页 `index.html` 顶栏声明条、首页「政策与合规声明」块、`CLAUDE.md` 三处均写明该日期；改动内容时若基线前移，三处同步更新。
2. **不引用具体文号**。`policy` 模块只写法律法规与制度的**名称与作用**（如《电力法》《供电营业规则》《供电监管办法》），一律注明「以现行有效文件为准」；**不得编造标准编号与文号**。
3. **合规红线**：本站**不提供任何规避监管的做法**，不给出具体业务办理的结论性建议，不教任何降低电费支出的非常规手段。涉及违约用电与窃电之处，只讲认定逻辑与处理原则，并强调「依法依规、程序合规、不得超授权」。
4. **客户信息保护的强调**：凡涉及客户数据之处（客户画像、营销数字化、用电检查、稽查），均须强调目的明确、最小必要、授权同意与安全防护。
5. **工具结果的免责**：五件互动工具均为极度简化教学测算，必须注明「不作为业务办理、收费、结算、合规或法律依据」。

## 技术架构

- 全局命名空间：`window.EMK`；localStorage 前缀 `emk.`（`emk.progress.v1`）；同步配置 `emk.sync.v1`；同步路径 `progress/power-marketing.json`。
- 引擎完全沿用 EMT：`registry / progress / sync / ui / engine / views-*` 逐行同构（仅 `EMT`→`EMK`、`emt.`→`emk.`）。
- 课时五段式：① 一句话 · ② 讲透 · ③ 别踩坑 · ④ 想一想（quiz，即时判分） · ⑤ 接着读。
- 内容即数据：`EMK.registerLesson({ id, module, order, title, minutes, keywords, concept, core, pitfalls, quiz, links })`。

## 5 个互动工具（views-tools.js）

1. **电费清单测算器**（`EMK.calcBill`）：计费方式 + 电量 + 电价 + 容量/需量 + 功率因数 + 基金附加 → 电度电费、基本电费、力率调整、合计与平均电价
2. **功率因数与无功补偿测算器**（`EMK.calcPF`）：有功功率 + 当前与目标功率因数 + 考核标准 + 电费基数 → 需补偿 kvar、可释放变压器容量、力率调整比例与年节省电费
3. **业扩报装方案测算器**（`EMK.calcConnect`）：报装容量 + 用电类别 + 电源 + 是否受电工程 → 建议供电电压、计量方式、办电环节与时限参考
4. **需求响应收益测算器**（`EMK.calcDR`）：可调容量 + 时长 + 削减率 + 次数 + 补偿标准 + 原电价 → 单次与全年补偿收益、含电费节省的合计、单位容量收益
5. **客户电费风险评分器**（`EMK.calcRisk`）：月均电费 + 欠费次数与天数 + 缴费率 + 客户类型 + 经营状况 → 风险评分、等级与服务策略建议

工具用 `oninput="EMK.calcXxx()"` 即时计算（不是按钮触发），`EMK.views.calc` 渲染后立即调用五个函数出首屏结果。

## 内容源写法陷阱

- ⚠️ **本站引擎（EMT 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**，与 NPS 系的 `module.exports = [...]` 完全不同：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>前文' + g('term-id','显示文字') + '后文</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号，正文标点用**全角**（，。：）
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。克隆基座后要**先删掉旧的 `<script src="content/...">` 标签**（保留 `modules.js` 与 `terms.js`），否则新旧脚本会同时加载。
- 克隆基座的命名空间替换要跑两遍：`sed "s/\bEMT\b/EMK/g; s/\bemt\b/emk/g"` 之后，还有一个坑——**`\nEMT.` 这类「反斜杠+n 紧邻」的位置词边界不成立**，`build.js` 里 `'\nEMT.registerLesson('` 与 `'\nEMT.terms = '` 会漏掉，需再补一次 `sed "s/EMT\./EMK./g"`。同理 `progress/power-market.json` 要单独替换为 `progress/power-marketing.json`。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语链接共 108 处、覆盖 100/102 个术语，密度约 1.2 处/课（基准站 EMT 为 141 处/106 课、约 1.3 处/课）。
