# AI 算力基础设施与算电协同 · AIC

大白话讲透 AI 算力基础设施与算电协同（科普通识，非工程设计与投资依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→AIC 命名空间替换），内容完全重写。「今日得到」合集第 45 站。

## 站点定位

- **给谁看**：电力与 IT 双栖的售前、方案、项目经理、交付实施与运维人员；关心「AI 底座怎么建、怎么供、怎么算、又怎么和电打交道」的跨专业读者。
- **讲什么**：算力度量与加速卡、集群组网与并行、训练与推理、Token 成本与算力经济、数据中心电气、散热与 PUE、AI 负荷与电网、智算中心选址与建设、算力网络与调度、算电协同、政策标准与合规、实战与展望。
- **不讲什么**：具体芯片型号与报价、真实的互联与能效标准编号、具体工程的设计计算、招投标条款。重「机制与判断」，轻「型号与参数」。
- **调性**：大白话、五分钟一课、有判断。先给一句人话，再展机制，最后落到「所以选型/方案/算账该怎么想」。

## 与兄弟站的关系

- **AIP（人工智能+电力）** 讲 AI 在电力业务中的应用场景；**AGT（AI 智能体）** 讲智能体架构；**ML（机器学习）** 讲算法与模型原理；**CCN（云计算与云原生）** 讲云上方法论；**PGF（电网通识）** 讲电力系统原理；**IOT（电力物联网与感知层）** 讲现场感知到平台接入。
- **本站（AIC）** 补的是这些站都不覆盖的**物理算力底座**：芯片怎么算、集群怎么连、训练与推理怎么跑、成本怎么摊、电从哪来、热往哪走、算力怎么跟着电走。因此本站不重复讲 AI 应用场景、不重复讲算法原理、不重复讲云原生方法论、不重复讲电力系统基础。

## ⚠️ 技术与合规（本站最硬的约束）

1. **内容基线：2026 年 10 月**。`index.html` 顶栏声明条、首页「技术与合规声明」块、`CLAUDE.md` 三处均写明该日期；基线前移时三处同步更新。

## 7 个互动工具（views-tools.js）

1. **Token 成本测算器**（`AIC.calcTokenCost`）：卡数 + 单卡功率与采购价 + 折旧年限 + PUE + 电价 + 单卡吞吐 + 利用率 → IT 功率、含 PUE 总功率、年耗电与电费、年折旧、年总成本、年产出 token、每百万 token 成本、电费与折旧占比
2. **PUE 与电费测算器**（`AIC.calcPue`）：IT 功率 + 制冷 + 供配电损耗 + 其他 + 电价 + 年小时 → PUE、各项占比、年耗电与电费、PUE 每降 0.1 的年节省
3. **机柜功率密度与散热选型器**（`AIC.calcRackDensity`）：单柜卡数与功耗 + 其他设备 + 机柜数 + 风冷/冷板上限 → 单柜功率密度、风冷占用率、推荐散热方式（风冷/冷板/浸没）、需液冷带走的功率、需配套冷量
4. **智算中心选址评分器**（`AIC.calcSiteScore`）：电力/网络/气候/政策电价/人才运维五项评分与权重 → 加权总分、评级、短板项、短板补齐潜在增益
5. **绿电直供经济性测算器**（`AIC.calcGreenDirect`）：年用电 + 电网与绿电电价 + 直供比例 + 专线投资 + 运营年限 + 两种碳因子 → 直供电量、年省电费、投资回收期、全周期净收益、年减碳与累计减碳
6. **算电协同收益测算器**（`AIC.calcSynergy`）：可调负荷 + 可调小时 + 峰谷价差 + 需求响应补偿 + 参与率 + 年 token 产出 → 有效可调负荷、削峰填谷与需求响应收益、综合年收益、折算每百万 token、单位可调负荷年收益
7. **算力 TCO 测算器**（`AIC.calcTco`）：加速卡/服务器网络/机房供电三项投资 + 年电费与运维 + 运营年限 + 年 token 产出 → CAPEX 与 OPEX、全周期 TCO、资本与运营占比、每百万 token TCO、电费占运营比

工具用 `oninput="AIC.calcXxx()"` 即时计算（不是按钮触发），`AIC.views.calc` 渲染后立即调用七个函数出首屏结果。

## 内容源写法陷阱

- ⚠️ **本站引擎（IOT 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**，与 NPS 系的 `module.exports = [...]` 完全不同：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>数据要走 ' + g('rdma','RDMA') + ' 这条通道。</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号。正文标点沿用全站既有风格：**逗号/冒号/问号/分号用半角**（`,` `:` `?` `;`），**句号用全角 `。`**，引号用「」。全站 `_src` 文件里全角逗号与全角冒号的出现次数均为 0。
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。克隆基座后要**先删掉旧的 `<script src="content/...">` 标签**（保留 `modules.js` 与 `terms.js`），否则新旧脚本会同时加载。
- 克隆基座的命名空间替换要跑三遍：`perl` 之后还有两个坑——① **`\b` 词边界在 macOS 的 BSD sed 里不生效**，必须用 `perl -pi -e 's/\bIOT\b/AIC/g'`；② `iotSVG` / `iotup0` 这类**驼峰标识符**（`iot` 后面紧跟字母，无词边界）正则抓不到，需单独处理；③ **`\nIOT.xxx` 形式**（字符串字面量里 `\n` 的 `n` 与 `IOT` 相邻，`\b` 不成立）也会漏替，须用 `perl -pi -e 's/IOT\./AIC./g'` 兜底。同理 `progress/iot-sensing.json` 要单独替换为 `progress/ai-compute.json`。
- **macOS 的 BSD grep 不支持 `\b` / `\|` / `\s`**，验证残留时**不要用 `grep -E '\bIOT\b'`**（会因 `\b` 失效得到"没有残留"的假阴性，且查中文行也会假阴性），要用 `grep -rn 'IOT'` 直接搜。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语标注覆盖全部 127 个术语，分布在各模块。
