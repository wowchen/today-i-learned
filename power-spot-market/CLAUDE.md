# power-spot-market — 电力现货与交易实务（Today I Learned 第 52 站）

大白话讲透「电怎么在现货市场里定出价格、交易员怎么报价与结算、偏差怎么考核、辅助服务与容量怎么看」（科普通识，非交易、报价、投资、结算或法律依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→SPOT 命名空间替换），内容完全重写。「今日得到」合集第 52 站。

## 给谁看 / 讲什么 / 不讲什么 / 调性
- **给谁看**：发电企业的报价与交易岗、售电公司的交易与结算岗、调度与市场运营人员、要参与现货的工商业用户与能源服务商，以及想读懂「现货」「负电价」「偏差考核」「容量电价」新闻的普通人。
- **讲什么**：现货的**操作与算账链**——为什么要有现货 → 与中长期怎么分工 → 出清怎么算 → 报价怎么定 → 结算与偏差怎么算 → 交易员一天怎么过 → 售电公司怎么赚钱 → 风险怎么对冲 → 辅助服务能挣多少 → 容量机制怎么补 → 绿电怎么进现货 → 预测与数据怎么用 → 监管与合规怎么守 → 真实市场怎么复盘 → 交易员怎么成长。
- **不讲什么**：不重复电力市场的交易品种全貌与制度演进（`power-market` 电力市场）、不重复能源政策与碳市场的规则与核算（`energy-carbon`）、不重复电网调度的物理运行与安全校核实操（`power-dispatch`）、不重复传感与量测设备本身（`iot-sensing`）。本站讲的是**站在交易台前，价格怎么来、怎么报、怎么结、怎么控**。
- **调性**：大白话、口语化、给具体数字例子（这一档报价中了多少度、偏差超了要罚多少、容量补偿每千瓦每年补多少），每课都给「能带走的一个判断」。

## 与兄弟站的边界
| 站 | 讲什么 | 本站不重复的地方 |
|---|---|---|
| `power-market` 电力市场 | 交易品种、出清与结算的制度全貌 | 只讲现货这一段怎么报、怎么算、怎么控，不铺开整个市场体系 |

## 技术与合规约束（必须有）
1. **常驻声明**：`index.html` 的 `.notice-bar`、首页 `.disclaimer`、课时页模块提示三处都要有，基线 **2026-10**。
2. **不构成依据**：`.notice-bar` 写明「本站不构成交易决策、报价、投资测算、结算或法律依据」；首页 `.disclaimer` 写明「本站为通识科普，不构成交易、报价、投资或结算依据」；课时页模块提示写明「本站不构成交易、报价、投资或结算依据」。
3. **口径随文件变**：涉及市场规则、出清机制、报价限额、结算口径、考核标准与价格水平之处，一律标注「以现行有效的市场规则、结算办法、交易中心公告与主管部门文件为准」。
4. **时效性强**：各省现货规则、报价上下限、考核带宽与分摊方式差异大且变化快，正文一律写「示例概数」并提醒读者核对最新规则。
5. **不引战、不预测**：不对电价走势、市场规则松紧作预测或倾向性评价；只讲机制与算法怎么运作。

## 7 件互动工具（`views-tools.js`）
| 函数 | 结果容器 | 算法要点 |
|---|---|---|
| `calcSpotCost` | `sc-result` | 现货综合价 = 日前均价×70% + 实时均价×30%；电量按敞口比例拆成中长期与现货；总成本 = 中长期成本 + 现货成本；加权均价 = 总成本 ÷ 总用电量；与「全中长期基准」比出省/多花；再叠加偏差考核费用（总用电量 × 偏差率 × 考核单价）得综合单价 |
| `calcBidRevenue` | `br-result` | 中标判定只看「报价 ≤ 出清价」；中标电量 = 容量 × 可发电小时 × 中标比例；收入 = 中标电量 × 出清价；毛利润 = 收入 − 中标电量 × 变动成本；度电毛利 = 毛利润 ÷ 中标电量 |
| `calcDeviation` | `dev-result` | 偏差率 =（实际 − 计划）÷ 计划；超出带宽百分点 = max(|偏差率| − 免考核带宽, 0)；考核电量 = 计划电量 × 超出百分点；考核费用 = 考核电量 × 考核单价；带宽以内费用为 0 |
| `calcAncillaryRevenue` | `ar-result` | 容量补偿 = 可调节容量 × 容量补偿单价；调频里程 = 可调节容量 × 调用小时 × 里程单价；调峰 = 年调峰电量 × 调峰单价；三者相加为合计，并各算占比 |
| `calcCapacityNeed` | `cn-result` | 需求容量 = 峰荷 ×（1 + 备用率）；固定成本总额 = 需求容量 × 单位固定成本；能量市场毛利 = 需求容量 × 利用小时 ×（能量均价 − 变动成本）；缺失资金 = max(固定成本 − 毛利, 0)；所需容量补偿单价 = 缺失资金 ÷ 需求容量（万元÷万 kW 即元/kW） |
| `calcPriceForecast` | `pf-result` | 预测/实际成本 = 锁价电量 × 中长期电价 + 敞口电量 × 预测/实际现货价；成本偏差 = 实际 − 预测；预测误差率 =（实际 − 预测）÷ 预测；另给 0%/10%/20%/30% 敞口敏感性对照表 |
| `calcTradingRisk` | `tr-result` | 敞口电量 = 总持仓 − 已锁价；敞口货值 = 敞口电量 × 现货价；单日风险值（简化 VaR）= 敞口货值 × 日波动率 × 置信系数（1.65≈95%、2.33≈99%）；再算把敞口压到 10% 后的风险降幅 |

## 内容源写法陷阱（`tools/_src/*.js`）
- 本站引擎（IOT 系）的 `_src/*.js` 是「**裸赋值 + helpers**」写法：`L.<moduleid> = [ ... ];`（如 `L.spotbasics`），由 `build.js` 用 `eval()` 加载，**不要写 `module.exports`**。
- helpers 只有 `g/ex/pit/fml/qc`，**没有 `qf`**；只能在引号外用 `+` 拼接。
- ⚠️ `L.eval = [` 这类模块 id 若恰好叫 `eval`，会与 `eval()` 冲突——本站无此问题，但命名模块时留意保留字。
- 课时元组**顶格从 `[` 开始**（不要缩进），9 元素：`[slug, 标题, 分钟, [关键词], concept, core, pitfalls, quiz数组, links]`。
- ⚠️ **`core` 必须是数组**（每项一个「小标题 + 正文」块）；写成字符串会导致 `build.js` 抛 `(les[7] || []).forEach is not a function`。
- concept 必须以「一句话:」开头；逗号/冒号/问号/分号用**半角**，句号用**全角 `。`**；引号「」，破折号 `——`；**禁止 emoji**。
- `tools/_src` 文件用 `NN-<moduleid>.js` 编号；插入模块后必须 `mv` 重排编号。
- ⚠️ **`cp -R` 克隆时若目标目录已存在会套一层**；克隆后必须 `ls` 确认没有多余嵌套。
- ⚠️ BSD/macOS 的 `sed` 无 `\b`（用 `perl -pi -e`）；Bash `grep` 查中文行易假阴性（用 Grep 工具/ripgrep）。
- ⚠️ **zsh 不对未加引号的 `$VAR` 做词分割**：`perl -pi -e '...' $FILES` 会把整串当一个文件名（报 `File name too long`），须改用 `find ... -print0 | xargs -0 perl -pi -e '...'`。
