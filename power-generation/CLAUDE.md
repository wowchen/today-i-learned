# 发电技术通识 · GEN

大白话讲透「电是怎么发出来的」（科普通识，非工程设计与设备选型依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→GEN 命名空间替换），内容完全重写。「今日得到」合集第 46 站。

## 站点定位

- **给谁看**：做电力信息化、配网智能化、跨域集成的售前、项目经理、交付实施与运维人员；以及需要把「电厂这一侧怎么发电」讲清楚、写进方案里的商务与技术角色。
- **讲什么**：发电总论（电源结构、基荷腰荷峰荷、容量系数与利用小时、度电成本），火电三大主机（锅炉-汽轮机-发电机）与朗肯循环、蒸汽参数、超超临界，锅炉与燃烧（制粉、煤粉、脱硫脱硝），汽轮机与热力系统（凝汽器、回热、再热、冷却塔、热耗率），发电机与励磁，环保与超低排放，煤电灵活性与调峰，水电与抽水蓄能，核电，风电，光伏，电厂电气与厂用电，并网与厂网协调，运维、碳与展望（碳市场、绿电、生物质、CCUS、虚拟电厂）。
- **不讲什么**：具体厂商型号与报价、真实的机组设计计算、招投标条款、电网侧与配电侧网架与调度（另有专站）。重「原理与判断」，轻「型号与参数」。
- **调性**：大白话、五分钟一课、有判断。先给一句人话，再展机制，最后落到「所以工程上该怎么理解」。

## 与兄弟站的关系

- **PGF（电网通识）** 讲电力系统原理与电网侧；**PDN（配电网与配电自动化）** 讲配电网架与自动化；**DSP（电力调度与二次系统）** 讲调度指挥与二次系统；**PEQ（输变电一次设备）** 讲变电侧设备本体；**EMK（电力营销）** 讲营销与用采；**IOT（电力物联网与感知层）** 讲感知层到平台这一段；**CCN（云计算与云原生）** 讲云上方法论。
- **本站（GEN）** 补的是这些站都不覆盖的一段：**电源侧——电到底是怎么从煤、水、铀、风、光里发出来的**。因此本站不重复讲电网运行、不重复讲配网网架、不重复讲调度与二次系统、不重复讲设备本体（变压器/开关等归 PEQ）。

## ⚠️ 技术与合规（本站最硬的约束）

1. **内容基线：2026 年 10 月**。`index.html` 顶栏声明条、首页「技术与合规声明」块、模块页提示、`CLAUDE.md` 四处均写明该日期；基线前移时同步更新。
2. **不写厂商名、不写报价、不写真实机型编号**。所有机组与装备描述停留在「原理与形态」层面。
3. **不编造标准编号与政策文号**。涉及环保限值、能效指标、电价机制与市场规则之处，只写口径与作用，一律注明「以现行有效标准与文件为准」。
4. **不给出结论性的选型/设计建议**。互动工具只给判断思路与量级，最终须以设计文件、厂商资料与企业技术规定为准。
5. **工具结果的免责**：七件互动工具均为极度简化教学测算，必须注明「不作为工程设计、设备选型、投标报价或合规依据」。

## 7 个互动工具（views-tools.js）

1. **发电度电成本测算器**（`GEN.calcLcoe`）：装机容量 + 单位造价 + 年利用小时 + 运维费率 + 折现率 + 运营年限 + 燃料成本 → 静态总投资、资本回收系数(CRF)、年发电量、年均资本/运维/燃料三项、**平准化度电成本 LCOE**、成本构成占比、全周期总成本；判断属「燃料主导型」还是「投资主导型」
2. **供电煤耗与碳排放测算器**（`GEN.calcCoalCarbon`）：年发电量 + 供电煤耗 + 厂用电率 + 标煤碳排放因子 → 发电煤耗、供电量、年耗标煤、**年 CO₂ 排放**、度电碳排放强度；点出「煤耗 × 排放因子 = 度电碳排放」这条链
3. **厂用电率与上网电量测算器**（`GEN.calcAuxRate`）：发电量 + 综合厂用电率 + 送出线损率 → 厂用电量、关口上网电量、线损电量、到网(售电)电量、发电→售电综合损耗；讲清「上网电量 = 发电量 ×(1 − 厂用电率)」
4. **风电光伏发电量测算器**（`GEN.calcWindSolarOutput`）：类型(风/光) + 装机容量 + 毛利用小时 + 综合效率 + 弃电率 → 理论/可用/上网电量、弃电损失、**等效利用小时、容量系数**、日均发电量、全生命周期累计
5. **抽水蓄能效率与收益测算器**（`GEN.calcPumpedStorage`）：单次用水量 + 水头 + 综合效率 + 年循环次数 + 上网电价 + 抽水电价 → 单次发电量(9.81×V×H×η÷3600)、抽水耗电、效率损失、单次/年度净收益、**峰谷价差**与盈亏判断
6. **调峰深度与收益测算器**（`GEN.calcPeakingBenefit`）：机组容量 + 最小技术出力 + 平均调峰出力 + 年调峰小时 + 补偿价 → 调峰深度、可下调容量、年调峰电量（让出电量）、年调峰收益、是否进入深度调峰区间
7. **环保排放达标校核器**（`GEN.calcEmissionCheck`）：执行标准(超低排放 10/35/50 或一般 30/100/100) + 烟尘/SO₂/NOx 实测 + 标态烟气量 + 年运行小时 → 三项逐项对比限值、占限值百分比与余量、年排放总量、综合达标结论与超标处理方向

工具用 `oninput="GEN.calcXxx()"` 即时计算（不是按钮触发），`GEN.views.calc` 渲染后立即调用七个函数出首屏结果。

## 内容源写法陷阱

- ⚠️ **本站引擎（IOT 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**，与 NPS 系的 `module.exports = [...]` 完全不同：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`（课时元组顶格从 `[` 开始，不缩进）
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>前文' + g('lcoe','LCOE') + '后文</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号。正文标点沿用全站既有风格：**逗号/冒号/问号/分号用半角**（`,` `:` `?` `;`），**句号用全角 `。`**，引号用「」。
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。克隆基座后要**先删掉旧的 `<script src="content/...">` 标签**（保留 `modules.js` 与 `terms.js`），否则新旧脚本会同时加载。
- **命名空间替换要跑三遍**（IOT→GEN）：① `perl -pi -e 's/\bIOT\b/GEN/g'`（macOS 的 BSD sed 无 `\b` 词边界，必须用 perl）；② `perl -pi -e 's/IOT\./GEN./g'` 兜底——`\b` 在 `'...\nIOT.terms = '` 这类字符串字面量里**不生效**（`\n` 是字母 n，与 `IOT` 之间无词边界），单独跑 ① 会漏掉 `build.js` 里以 `IOT.` 开头的注入代码；③ 驼峰标识符（`iotSVG` / `iotup0` / `iotdn0`）正则抓不到，需随 views 重写一并清除。同理 `progress/<旧站>.json` 要替换为 `progress/power-generation.json`。
- **macOS 的 BSD grep 不支持 `\|` 与 `\s`**，且**用 `grep` 查中文行容易假阴性**；验证残留时直接 `grep -rn 'IOT'` 全量搜。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语 124 个，分布在各模块；插入新模块后若改了 `_src` 文件编号，务必 `mv` 重排文件名，否则 `NN` 编号与模块顺序错位。
