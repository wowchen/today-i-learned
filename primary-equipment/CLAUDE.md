# 输变电一次设备通识 · PEQ

大白话讲透「变电站与线路里那些真正过电的设备」（科普通识，非工程设计与设备选型依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→PEQ 命名空间替换），内容完全重写。「今日得到」合集第 47 站。

## 站点定位

- **给谁看**：做电力信息化、配网智能化、跨域集成的售前、项目经理、交付实施与运维人员；以及需要把「一次设备这一侧」讲清楚、写进方案里的商务与技术角色。
- **讲什么**：一次设备总论（一次与二次分工、额定电压/电流/容量、绝缘水平、短路电流与动热稳定、选型原则），变压器（原理、油浸与干式、铁芯绕组、套管、分接开关、冷却、损耗、负载率），断路器与 GIS（灭弧原理、SF6 与真空、开断能力、操动机构、AIS/GIS/HGIS、重合闸），隔离开关与开合设备（不能带负荷拉、接地开关、负荷开关、熔断器、组合电器、五防），互感器与测量（CT/PT/CVT、变比与准确级、极性、二次负荷、电子式），避雷器与过电压（过电压分类、MOA、雷电与操作过电压、接地、绝缘配合），绝缘子与金具（爬电比距、片数、污闪、金具），输电线路与导线电缆（架空与电缆、导线、弧垂张力、杆塔、载流量、电晕），母线与成套设备（母线、开关柜、环网柜、铠装式金属封闭、间隔、电缆终端），电气布置与主接线（单/双母线、桥式、一个半断路器、线路-变压器组），状态评价与试验（交接/预防性试验、绝缘电阻与介损、局放、油色谱、在线监测、状态评价），全寿命周期管理（LCC、资产管理、可用率、技改、退役、备品、TCO），智能运检与数字化（状态监测、机器人与无人机、感知终端、数字孪生、边缘计算、IEC 61850），典型故障与事故。
- **不讲什么**：具体厂商型号与报价、真实的选型计算与试验数据、招投标条款、电网侧网架与调度（另有专站）。重「原理与判断」，轻「型号与参数」。
- **调性**：大白话、五分钟一课、有判断。先给一句人话，再展机制，最后落到「所以选型/运维该怎么想」。

## 与兄弟站的关系

- **PGF（电网通识）** 讲电力系统原理与网架；**PDN（配电网与配电自动化）** 讲配电网架与自动化；**GEN（发电技术通识）** 讲电源侧怎么发电；**DSP（电力调度与二次系统）** 讲调度指挥与二次系统；**IOT（电力物联网与感知层）** 讲感知层到平台这一段；**EMK（电力营销）** 讲营销与用采；**CCN（云计算与云原生）** 讲云上方法论。
- **本站（PEQ）** 补的是这些站都不覆盖的一段：**变电站与线路里那些"真正过电"的设备本体**——它是什么、怎么工作、怎么选、怎么试、怎么管。因此本站不重复讲系统原理、不重复讲配网网架、不重复讲发电原理、不重复讲调度与二次系统、不重复讲感知与通信。

## ⚠️ 技术与合规（本站最硬的约束）

1. **内容基线：2026 年 10 月**。`index.html` 顶栏声明条、首页「技术与合规声明」块、模块页提示、`CLAUDE.md` 四处均写明该日期；基线前移时同步更新。
2. **不写厂商名、不写报价、不写真实型号编号**。所有设备描述停留在「原理与形态」层面。
3. **不编造标准编号与政策文号**。涉及设备参数、绝缘配合、短路校核、试验项目、反措要求之处，只写口径与作用，一律注明「以现行有效标准与文件为准」。
4. **不给出结论性的选型/设计建议**。互动工具只给判断思路与量级，最终须以设计文件、现行标准与企业技术规定为准。
5. **工具结果的免责**：七件互动工具均为极度简化教学测算，必须注明「不作为工程设计、设备选型、投标报价或运维作业依据」。

## 技术架构

- 全局命名空间：`window.PEQ`；localStorage 前缀 `peq.`（`peq.progress.v1`）；同步配置 `peq.sync.v1`；同步路径 `progress/primary-equipment.json`。
- 引擎完全沿用 IOT：`registry / progress / sync / ui / engine / views-*` 逐行同构（仅 `IOT`→`PEQ`、`iot.`→`peq.`）。
- 课时五段式：① 一句话 · ② 讲透 · ③ 别踩坑 · ④ 想一想（quiz，即时判分） · ⑤ 接着读。

## 7 个互动工具（views-tools.js）

1. **变压器负载率与损耗测算器**（`PEQ.calcTransformerLoad`）：额定容量 + 实际负载与功率因数 + 空载损耗 + 额定负载损耗 + 年运行小时 + 电价 → 负载率 β、经济负载率 √(P0/Pk)、铜损 = β²·Pk、综合损耗功率、年损耗电量与电费、效率、是否过载
2. **短路电流与开断能力校核器**（`PEQ.calcShortCircuit`）：标称电压 + 系统短路容量 + 断路器额定开断电流 + 短路持续时间 + 设备短时耐受电流与耐受时间 → 三相短路电流 I = S/(√3·U)、冲击电流 ip = 2.55·I、热效应 Q = I²·t 与允许值 Q_allow = Ith²·tth 对比、开断能力校核
3. **避雷器与绝缘配合校核器**（`PEQ.calcInsulationCoord`）：Um + 避雷器额定电压 + 标称放电电流下残压 + 设备 BIL + 要求配合系数 → 需要的耐受水平 = 残压×(1+系数)、实际配合系数 = BIL/残压、是否满足配合要求
4. **绝缘子片数与爬距校核器**（`PEQ.calcInsulatorString`）：Um + 污区要求爬电比距 + 单片爬距 + 单片结构高度 + 海拔 → 需要爬距 = Um×比距、海拔修正系数、所需片数（向上取整）、串长校核
5. **载流量与截面选型器**（`PEQ.calcAmpacity`）：导体材质（铝/铜）+ 计算负荷电流 + 环境温度 + 允许温度 + 并列修正系数 → 温度修正系数 kt = √((tc−ta)/(tc−25))、所需基准载流量、内置 SEC/AL/CU 截面-载流量表比对选型
6. **导线弧垂与张力测算器**（`PEQ.calcSagTension`）：档距 + 导线单位重量 + 水平张力 + 挂点对地高度 + 最小对地安全距离 + 计算拉断力 → 弧垂 f = wL²/(8T)、最低点对地高度校核、张力占拉断力比例校核
7. **设备全寿命成本(LCC)测算器**（`PEQ.calcLcc`）：购置费 + 安装费 + 年运维费 + 年损耗电费 + 寿命年数 + 贴现率 + 残值 → 年金现值系数、运维与损耗现值、残值现值、LCC 与年化成本、各项占比

工具用 `oninput="PEQ.calcXxx()"` 即时计算（不是按钮触发），`PEQ.views.calc` 渲染后立即调用七个函数出首屏结果。

## 内容源写法陷阱

- ⚠️ **本站引擎（IOT 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`（课时元组**顶格从 `[` 开始、不缩进**）
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>前文' + g('rated-voltage','额定电压') + '后文</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号。正文标点沿用全站既有风格：**逗号/冒号/问号/分号用半角**（`,` `:` `?` `;`），**句号用全角 `。`**，引号用「」。
  - **必须在写课时前先把 `TERMS` 定死并产出「可用术语 id 白名单」**，agent 只能用白名单内 id，否则构建会因 `data-term` 未定义而报错。
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。克隆基座后要**先删掉旧的 `<script src="content/...">` 标签**（保留 `modules.js` 与 `terms.js`），否则新旧脚本会同时加载。
- 克隆基座的命名空间替换要跑三遍（本次 IOT→PEQ 实测）：① `perl -pi -e 's/\bIOT\b/PEQ/g'`（BSD `sed` 无 `\b`）；② 兜底 `perl -pi -e 's/IOT\./PEQ./g'`——`\b` 在 `'...\nIOT.terms = '` 这类**字符串字面量**里会失效（`n` 与 `IOT` 之间无词边界）；③ **驼峰标识符**（`iotSVG` / `iotup0` / `iotdn0`）正则抓不到，需单独替换（本站已随 views 重写清除）。同理 `progress/iot-sensing.json` 要替换为 `progress/primary-equipment.json`。
- **macOS 的 BSD grep 不支持 `\|` 与 `\s`**，且**对中文行会假阴性**——验证残留时中文关键词一律用 Grep 工具（ripgrep）查，不要用 Bash `grep`。
- 统计课时数不要用 grep 数行（课时元组顶格 + 中文行假阴性）；用 `node` 求值精确统计。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语标注覆盖全部 126 个术语，分布在各模块。
