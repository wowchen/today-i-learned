# energy-carbon — 能源政策与碳市场（Today I Learned 第 51 站）

大白话讲透「能源怎么管、电怎么定价、碳怎么算、碳怎么交易、绿电绿证怎么用」（科普通识，非投资、交易、报价、审计或法律依据）。克隆 `iot-sensing`(IOT) 共享引擎（IOT→ENC 命名空间替换），内容完全重写。「今日得到」合集第 51 站。

## 给谁看 / 讲什么 / 不讲什么 / 调性
- **给谁看**：能源/电力行业从业者（营销、规划、调度、售电、用能服务）、企业的能源与碳管理岗位、要参与碳市场或绿电采购的商务与管理者，以及想读懂「双碳」「碳价」「绿电」新闻的普通人。
- **讲什么**：政策与体制的**因果链**——能源政策怎么定 → 电力体制怎么改 → 电价怎么算 → 可再生能源怎么扶 → 双碳目标怎么落 → 碳怎么核算 → 碳市场怎么运转 → 全国与地方碳市场怎么衔接 → CCER 与绿证绿电怎么用 → 碳怎么变成资产 → 国际规则与碳关税怎么影响出口 → 企业碳管理实务。
- **不讲什么**：不重复电力市场的交易品种与出清算法（`power-market` 电力市场）、不重复储能的设备与配置（`new-power-storage`）、不重复五年规划的政策文本通读（`fifteenth-five-year-plan`）、不重复企业财税与审计操作（`enterprise-finance`）、不重复营销业务与客户服务（`power-marketing`）。本站讲的是**给能源定价、给碳定价背后的规则与判断**。
- **调性**：大白话、口语化、给具体场景例子（电费单怎么构成、配额缺口要花多少钱、出口被收多少碳关税、绿电比火电多挣多少），每课都给「能带走的一个判断」。

## 技术与合规约束（必须有）
1. **常驻声明**：`index.html` 的 `.notice-bar`、首页 `.disclaimer`、课时页模块提示三处都要有，基线 **2026-10**。
2. **不构成依据**：一律写明「通识科普，不构成投资、交易、报价、审计或法律依据」。
3. **口径随文件变**：涉及法规条文、政策口径、标准编号、配额分配方案、CBAM 实施细则、市场行情之处，标注「以现行法律法规、主管机构规则与真实市场数据为准」。
4. **时效性强**：碳价、配额比例、绿证价格、CBAM 时间表变化快，正文一律写「示例概数」并提醒读者核对最新规则。
5. **不引战、不预测**：不对碳价走势、政策松紧作预测或倾向性评价；只讲机制怎么运作。

## 7 件互动工具（`views-tools.js`）
| 函数 | 结果容器 | 算法要点 |
|---|---|---|
| `calcEmission` | `ce-result` | 电力间接排放 = 外购电量×电网因子；燃煤 = 吨标煤×2.66；天然气 = 万 Nm³×因子；合计 + 折算综合能耗（电 1.229 tce/万 kWh、气 13.3 tce/万 Nm³）+ 单位电量排放强度 |
| `calcAllowance` | `ca-result` | 缺口 = 排放 − 免费配额 − 结余；抵消上限 = 排放×比例；抵消用量 = min(缺口,上限)；购配额成本 + 抵消成本 = 履约总成本；吨排放边际成本 |
| `calcCbam` | `cb-result` | 应缴碳量 = 出口量×内含排放×(1−免费比例)；应收 = 应缴×进口方碳价；抵扣 = 应缴×本国碳价；净应缴；单吨产品碳成本 |
| `calcGreen` | `gp-result` | 基础电费 = 电量×基准价；环境溢价 = 电量×溢价；绿证收入（证电分离时单列，合一并入溢价）；合计 + 可抵消排放（示例因子 5.7） |
| `calcRps` | `rp-result` | 应消纳 = 总电量×权重；达标率 = 已落实÷应消纳；缺口电量；需补绿证 = 缺口÷每张电量；达标成本 |
| `calcPeak` | `pk-result` | 达峰年限 = ln(目标/当前)÷ln(1+增速)；达峰年 = 基线年 + 年限；降到 10%/5% 年数 = ln(0.10|0.05)÷ln(1−降速)；距碳中和目标年数 + 降速是否够用 |
| `calcAbatement` | `ab-result` | 单位减排成本（万元→元/tCO₂）= 成本×10000÷减排量；按边际成本升序排序；与参考碳价比「自己做更划算还是买配额更划算」；加权平均成本 |

## 内容源写法陷阱（`tools/_src/*.js`）
- 本站引擎（IOT 系）的 `_src/*.js` 是「**裸赋值 + helpers**」写法：`L.<moduleid> = [ ... ];`，由 `build.js` 用 `eval()` 加载，**不要写 `module.exports`**。
- helpers 只有 `g/ex/pit/fml/qc`，**没有 `qf`**；只能在引号外用 `+` 拼接。
- ⚠️ `L.eval = [` 这类模块 id 若恰好叫 `eval`，会与 `eval()` 冲突——本站无此问题，但命名模块时留意保留字。
- 课时元组**顶格从 `[` 开始**（不要缩进），9 元素：`[slug, 标题, 分钟, [关键词], concept, core, pitfalls, quiz数组, links]`。
- ⚠️ **`core` 必须是数组**（每项一个「小标题 + 正文」块）；写成字符串会导致 `build.js` 抛 `(les[7] || []).forEach is not a function`。本站 `basics/04-energy-transition` 曾踩此坑。
- concept 必须以「一句话:」开头；逗号/冒号/问号/分号用**半角**，句号用**全角 `。`**；引号「」，破折号 `——`；**禁止 emoji**。
- `tools/_src` 文件用 `NN-<moduleid>.js` 编号；插入模块后必须 `mv` 重排编号。
- ⚠️ **`cp -R` 克隆时若目标目录已存在会套一层**；克隆后必须 `ls` 确认没有多余嵌套。
- ⚠️ BSD/macOS 的 `sed` 无 `\b`（用 `perl -pi -e`）；Bash `grep` 查中文行易假阴性（用 Grep 工具/ripgrep）。
- ⚠️ **zsh 不对未加引号的 `$VAR` 做词分割**：`perl -pi -e '...' $FILES` 会把整串当一个文件名（报 `File name too long`），须改用 `find ... -print0 | xargs -0 perl -pi -e '...'`。
