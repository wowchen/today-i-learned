# 电力调度与二次系统 · DSP

大白话讲透电力调度与二次系统（科普通识，非工程设计与定值整定依据）。克隆 `iot-sensing`(IOT，其自身克隆自 `power-marketing`/EMK) 共享引擎（IOT→DSP 命名空间替换），内容完全重写。「今日得到」合集第 44 站。

## 站点定位

- **给谁看**：做电力信息通信、调度自动化、配网智能化、跨域集成的售前、项目经理、交付实施与运维人员；以及需要把「调度是怎么指挥电网的、保护与稳控是怎么保住电网的」讲清楚、写进方案里的商务与技术角色。
- **讲什么**：调度体系与职责（五级调度）、电力系统运行基础（频率电压与三道防线）、二次系统总论、继电保护、安全稳定控制、调度自动化、调度通信与时钟、调度运行、新能源与有源调度、配网调度、二次安防、智能变电站与数字化二次系统、保护与稳控的现场工作、调度业务与实战。
- **不讲什么**：电力系统原理本身（已有 PGF 电网通识）、配电网网架与设备构成（已有 PDN 配电网与配电自动化）、光传输设备原理（已有 TCM 通信通识）、电力市场交易规则（已有 EMT 电力市场）。也不写真实型号、报价与工程计算。
- **调性**：大白话、五分钟一课、有判断。先给一句人话，再展机制，最后落到「所以现场该怎么想」。

## 与兄弟站的关系

- **PGF（电网通识）** 讲电力系统原理与发输变配用；**PDN（配电网与配电自动化）** 讲配电网架、设备与终端；**TCM（通信通识）** 讲传输光网络（SDH/OTN/PON）；**IOT（电力物联网与感知层）** 讲感知层到平台那段；**EMT（电力市场与能源交易）** 讲市场机制。
- **本站（DSP）** 补的是这几站都不覆盖的一段：**电网靠什么被指挥、靠什么被保护、靠什么保持稳定**——也就是调度体系与它手上那套二次系统。因此本站不重复讲电力系统原理、不重复讲配电网架、不重复讲光传输原理、不重复讲市场规则。

## ⚠️ 技术与合规（本站最硬的约束）

1. **内容基线：2026 年 9 月**。`index.html` 顶栏声明条、首页「技术与合规声明」块、`CLAUDE.md` 三处均写明该日期；基线前移时三处同步更新。

## 7 个互动工具（views-tools.js）

1. **频率偏差与功率缺额估算器**（`DSP.calcFreqDeficit`）：系统负荷 + 事件类型（缺额/过剩）+ 功率变化量 + 单位调节功率 K + 低频减载首轮定值 → 稳态频率偏差与稳态频率、变化量占负荷比例、触发首轮减载的临界变化量、距首轮裕度、是否触发低频减载
2. **AGC 调频备用测算器**（`DSP.calcAgcReserve`）：系统负荷 + 最大单机容量 + 备用系数 + 预测偏差率 + 机组调节速率 + 恢复时间 → 事故备用需求、波动备用需求、备用合计与备用率、一次调频可支撑缺额、AGC 需补足功率、所需在线可调容量及其占负荷比例
3. **继电保护定值校核器（过流）**（`DSP.calcRelaySetting`）：互感器变比 + 最大负荷电流 + 可靠系数 Krel + 返回系数 Kre + 末端最小短路电流 + 时间级差 + 要求灵敏系数 → 一次/二次动作电流定值、灵敏系数与是否满足、定值高出负荷电流的余量、本保护动作时间
4. **保护上下级配合校核器**（`DSP.calcCoordination`）：下级/上级一次定值 + 电流配合系数要求 + 两级动作时间 + 时间级差要求 + 上级范围末端最小短路电流 + 远后备灵敏系数要求 → 实际电流配合系数与余量、实际时间级差、远后备灵敏系数、上级定值的**建议区间**（下限保配合、上限保灵敏）、上级时间下限、三条线是否同时满足的配合结论，并识别「配合区间为空」的死结
5. **故障切除时间与稳定裕度估算器**（`DSP.calcClearTime`）：故障类型（三相/两相/单相）+ 通道时间 + 保护动作时间 + 断路器分闸时间 + 三相极限切除时间 → 三段合计的总切除时间、该类型折算后的极限切除时间、剩余裕度与裕度比例、分级判断（充足/偏紧/危险/失稳）
6. **低频减载轮次配置器**（`DSP.calcUfls`）：系统负荷 + 各轮频率定值（逗号分隔）+ 各轮切除比例（逗号分隔）+ 单位调节功率 K + 目标稳态频率 → 逐轮切除容量/累计切除/累计占比/该轮对应缺额、递减与轮次间隔校验、累计切除是否覆盖最严重缺额、全切后稳态频率估算
7. **新能源消纳与弃电测算器**（`DSP.calcCurtailment`）：新能源装机 + 日等效利用小时 + 日最大/最小负荷 + 常规机组最小技术出力率 + 外送能力 + 储能功率 + 大发时长 + 目标利用率 → 渗透率、理论日发电量、消纳空间三块构成（负荷侧/外送/储能）及占比、可消纳电量、弃电电量与弃电率、实际利用率、达标还需补多少 MW 空间

工具用 `oninput="DSP.calcXxx()"` 即时计算（不是按钮触发），`DSP.views.calc` 渲染后立即调用七个函数出首屏结果。轮次表用 `.cr-wide`（横向可滚动）。

## 内容源写法陷阱

- ⚠️ **本站引擎（IOT/EMK 系）的 `_src/*.js` 是「裸赋值 + helpers」写法**，与 NPS 系的 `module.exports = [...]` 完全不同：
  - 文件形如 `L.<moduleid> = [ [slug, 标题, 分钟, [关键词], concept, core, pitfalls, quizArray, links], ... ];`
  - 由 `build.js` 用 **`eval()`** 加载（不是 `require`），所以 helpers 在文件作用域内可用
  - helpers **只有 `g / ex / pit / fml / qc` 五个，没有 `qf`（填空题）**。写填空 quiz 会报 `ReferenceError: qf is not defined`，必须改用 `qc`。
  - `g()/ex()/pit()/fml()` 必须放在引号**外**、用 `+` 连接：`'<p>前文' + g('relay-protection','继电保护') + '后文</p>'`
  - 字符串统一用**单引号**，HTML 属性用双引号。正文标点沿用全站既有风格：**逗号/冒号/问号/分号用半角**（`,` `:` `?` `;`），**句号用全角 `。`**，引号用「」。全站 `_src` 文件里全角逗号与全角冒号的出现次数均为 0。
- 新增/修改内容后必须 `node tools/build.js`。构建校验会检查：`data-term` 是否在 `TERMS` 中定义、`#/l/` 与 `#/m/` 内链是否指向真实课时/模块、是否含 emoji。
- **`index.html` 的 `<!--LESSONS-->` 标记是幂等的**（`build.js` 替换为脚本列表 + 标记本身，重复 build 不重复注入）。
- 克隆基座的命名空间替换要跑两遍：① **`\b` 词边界在 macOS 的 BSD sed 里不生效**，必须用 `perl -pi -e 's/\bIOT\b/DSP/g'`；② `dspSVG` / `dspup0` / `dspdn0` 这类**驼峰标识符**（`iot` 后面紧跟字母，无词边界）正则抓不到，需随 views 重写清除。同理 `progress/iot-sensing.json` 要单独替换为 `progress/power-dispatch.json`。
- **macOS 的 BSD grep 不支持 `\|` 与 `\s`**，验证残留时要用 `grep -E 'A|B'`，否则会得到"没有残留"的假阴性。
- slug 一旦发布不要改（会打断已读进度与旧链接）。
- 本站术语标注覆盖全部 131 个术语，分布在各模块。
